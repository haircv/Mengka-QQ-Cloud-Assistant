# QQ云助手 v1.2.34

## 更新内容

- 修复萌卡插件卡片提示“插件管理端未就绪，请检查运行日志”：
  - 管理端新增 `/health`、`/healthz`、`/ready`、`/readyz`、`/api/health`、`/api/ready`、`/api/admin/ready` 等 JSON 探活，统一返回 `ready:true`。
  - 管理令牌识别扩展为任意名称含 `token`/`mengka` 的请求头、`Authorization: Bearer`、URL `token`/`access_token` 及名称含 token/admin 的 Cookie，兼容不同萌卡版本。
  - 管理端同时监听 IPv4 `0.0.0.0`、IPv6 `::1` 和局域网地址，API 仍强制校验管理令牌；避免萌卡通过 LAN IP 或 IPv6 探活时连接失败。
  - 不带尾斜杠的 `/web` 或挂载前缀改为直接返回 200 并注入 `<base>`，不再依赖 307 跳转；CSP 相应放行 `base-uri 'self'`，相对资源与 API 正常加载。
  - 启动日志记录管理端端口、挂载前缀、Origin、内嵌模式和令牌是否就绪；管理端记录页面/探活/API 请求及未通过鉴权的请求头名称（不记录令牌值），便于定位萌卡未连接或鉴权方式不一致。
- 后端增加 IPC `ready` 帧字段日志，便于排查萌卡是否下发额外的管理端信息。
- 同步更新 README、开发文档与三平台安装包。

## 升级说明

- 在“系统 → 在线更新”安装 1.2.34；若萌卡提示 `capability_change`，按控制台提示确认后会携带审批令牌重试。
- 安装后重新打开插件卡片点击“管理”。启动日志应出现“萌卡管理端配置”和“萌卡管理端已监听”。
- 若仍提示未就绪：
  - 日志中没有“萌卡管理端请求”或“请求未通过鉴权”，说明萌卡没有连到管理端口，请提供萌卡控制台日志及点击“管理”时打开的完整 URL。
  - 日志中有“请求未通过鉴权”，会列出萌卡实际发送的令牌相关请求头名称，可据此继续适配。
- 管理端监听局域网地址但 API 需要管理令牌，不建议直接暴露到公网。
