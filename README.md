# QQ云助手

**适用于萌卡 NT 3.0 的 QQ 助手，原生 IPC 接入，自带 Web 控制台。**

把群管理、自动化、问答、定时群发、点歌、红包助手和本地卡密授权放在一个管理页面里。插件 ID 为 `qq-cloud-assistant`，以 `native-ipc-v1` 随萌卡启动，不需要开放插件端口或填写服务令牌；支持 Windows x64、Linux x86_64 和 Linux ARM64。

所有配置、卡密和红包账本保存在本机数据目录。当前版本 **1.2.24**，代码声明 **382 条指令**，指令按节点能力自动注册；控制台共 **59 个模块**。

[下载安装包](https://github.com/haircv/Mengka-QQ-Cloud-Assistant/releases) · [更新日志](https://github.com/haircv/Mengka-QQ-Cloud-Assistant/releases) · [反馈问题](https://github.com/haircv/Mengka-QQ-Cloud-Assistant/issues)

## 可以做什么

| 分类 | 功能 |
| --- | --- |
| 群聊管理 | 踢人、禁言/解禁、上下管、全体禁言/解禁、解禁全部、禁言列表、群星/群信息、取码、复读、取直链、加群链接 |
| 提示通知 | 入群、退群、被踢、被删、机器人被踢通知与模板；默认关闭，按单个群开启 |
| 自动化 | 防撤、自身撤回、艾特处理、秒赞秒评、点赞、互赞、表情回应、续火、自动说说、自动处理、名片、打卡、资料、备注、头衔、入群验证 |
| 问答 | 本群/好友/全局 × 精准/模糊，白名单、延迟、随机回复条数、关键词冷却 |
| 定时与群发 | 定时/循环任务、群发群/好友/群名片、定时禁言/解禁/打卡；任务可在控制台启用、暂停和删除 |
| 点歌 | QQ/网易云/酷狗多源搜索、选歌、链接/语音/音乐卡片回复、线路优先级与失败换源 |
| 红包助手 | 普通/拼手气/口令/专属/语音五类自动领取、关键词包含/排除、期望过滤、拟人延迟、到账回复、只领不回复名单、分群配置、账本与排行 |
| 授权 | 本地卡密生成/禁用/删除、群主兑换、分群授权与续期、代理配额、可选授权门禁 |
| 账号与权限 | 六级权限、主人菜单、触发模式、账号分组、主群；同一 QQ 多协议默认仅 Android 实例生效 |
| 控制台 | 59 个模块，覆盖总览、账号、群管理、自动化、问答、任务与点歌线路、红包、授权、权限、系统 |
| 在线更新 | GitHub Release 或自定义清单检查新版本，校验插件 ID/版本/SHA256 后在萌卡托管模式下导入并自动启用 |

红包助手依赖萌卡官方 `red_packet` 消息段和红包接口，要求 Android 协议账号；节点缺少对应能力时，红包相关指令不会注册，控制台会显示原因。

## 下载与导入

先准备正在运行的 [Mengka NT](https://github.com/Carlor-Official/Mengka-NT) 3.0，再下载对应系统的安装包。

| 系统 | 选择的文件 |
| --- | --- |
| Windows x64 | 文件名包含 `windows-amd64` 的 ZIP |
| Linux x64 | 文件名包含 `linux-amd64` 的 TAR.GZ |
| Linux ARM64 | 文件名包含 `linux-arm64` 的 TAR.GZ |

当前版本的三个安装包：

- `qq-cloud-assistant-1.2.24-windows-amd64.zip`
- `qq-cloud-assistant-1.2.24-linux-amd64.tar.gz`
- `qq-cloud-assistant-1.2.24-linux-arm64.tar.gz`

每个包根目录包含 `mengka-plugin.json`、本机可执行文件、`README.txt` 和 `SHA256SUMS`。不要只解压可执行文件去覆盖已安装目录后重启，萌卡会校验插件程序文件完整性。

### 导入

1. 在萌卡 NT 管理后台打开“插件 → 插件导入”。
2. 选择对应系统的安装包，绑定服务节点并确认权限。
3. 导入后启动插件。首次启动会在数据目录生成 `admin.token`，并向框架日志输出一次管理令牌。
4. 在运行插件的电脑上打开 **http://127.0.0.1:18084/**。
5. 托管模式默认使用萌卡管理员账号、密码和图形验证码登录；也可以点“使用本地管理令牌”，用 `admin` + 数据目录中的 `admin.token` 登录。勾选“30 天免登录”后，更新或重启插件仍会自动登录，手动退出后失效。

管理页面已内嵌在插件中，不需要另外安装 Go、Node.js 或 WebView2。

如果 18084 被占用，控制台会依次尝试 18085–18093，实际地址以日志输出为准。

控制台默认只监听 `127.0.0.1`。Linux 插件运行在远程电脑时，可在自己的电脑建立 SSH 端口转发：

```sh
ssh -L 18084:127.0.0.1:18084 user@host
```

保持连接后，在自己的浏览器打开 **http://127.0.0.1:18084**。

## 首次使用

1. 在“账号列表”确认账号与协议实例；同一 QQ 使用不同协议时，配置分别保存。
2. 在“主人”页添加主人 QQ。只给自己使用时，也可以直接用机器人自身 QQ 发指令，自身默认拥有 Lv5 权限。
3. 同一 QQ 的 Android 与 Linux/PC 实例同时在线时，默认仅 Android 实例响应，Linux/PC 静默；可在“触发模式”关闭“仅 Android 生效”。
4. 在“指令权限”选择“推荐”预设，或逐条下调需要开放给别人的指令。默认全部指令仅 Lv5 可用。
5. 发送“菜单”验证。机器人自身发送也会正常回复；非主人发送者仍受指令级别限制。

需要授权门禁时，在“授权 → 授权设置”开启，然后在“卡密管理”生成卡密。群主在群内发送 `使用卡密 <卡密>` 为本群开通或续期；如果群主不是主人，需要先把 `使用卡密` 指令级别下调到 Lv3。

## 权限

| 级别 | 名称 | 说明 |
| --- | --- | --- |
| 0 | 黑名单 | 不响应指令与交互式自动回复 |
| 1 | 群员 | 仅响应下调到 Lv1 的指令 |
| 2 | 管理 | 事件角色为管理员 |
| 3 | 群主 | 事件角色为群主 |
| 4 | 分管 | 群配置中的分管名单 |
| 5 | 主人 | 全局主人、账号主人、机器人自身 |

- 所有指令默认仅 Lv5 可触发，包括菜单、帮助、运行状态、红包、点歌和授权。
- 机器人自身 QQ 发送消息时直接判定 Lv5；自身消息不会进入问答、艾特、表情回应和防撤转发。
- 指令可配置级别为 1–5；`0` 是黑名单，不能分配给指令。
- 控制台提供“严格”和“推荐”两档预设，也可以逐条自定义。“推荐”会把菜单、帮助、本群打卡、申请头衔、加入/退出互赞、点歌下调到 Lv1，把运行状态、查共群、查询群星下调到 Lv3。
- 自动功能主要受功能开关、名单和授权门禁控制，不受指令级别限制；黑名单仍不响应交互式自动回复。

## 功能说明

### 提示与群管

入群、退群、被踢、被删和机器人被踢提示默认全部关闭。可在“群管理 → 提示功能”选中群后单独开启，或在群内发送 `开启入群提示`、`开启退群提示` 等指令；开启只写入当前群配置。

禁言/解禁支持 `@成员`、`@QQ号` 和直接填写 QQ 号；@ 段缺少数字 ID 时，会按昵称、UID 映射或引用消息回退解析。群管理操作使用当前 QQ 的群权限，需要当前账号具备相应身份。

### 自动化

自动化功能按账号保存，包含防撤、自身撤回、艾特处理、秒赞秒评、点赞、互赞、回应表情、续火、自动说说、自动处理、名片、打卡、资料、备注、头衔和入群验证。

- `防撤` 会把撤回消息的缓存原文发回当前会话；`自身撤回` 可延时撤回机器人自己发送的消息。
- `自动处理` 包含自动同意好友/进群、新好友回复和回赞等开关。
- `入群验证` 支持数字、字母、混合和发言验证，可设置超时时间及未验证时的踢出、禁言或不处理。
- 自动化主要受开关、名单和授权门禁控制，不需要把对应指令下调给普通成员；黑名单仍不响应交互式自动回复。

### 问答

问答分为本群、好友、全局三种范围，每种范围都有精准和模糊两种匹配方式。支持白名单、延迟回复、随机回复条数和关键词冷却。

```text
添加精准问 你好 你好，有什么可以帮你？
添加模糊问 晚安 晚安，做个好梦
查看精准问
删除精准问 你好
```

精准问按完整关键词匹配，模糊问按包含匹配；回复内容取关键词后的全部文本。

### 定时、循环与群发

任务按账号保存，可在“任务与群发”页面查看下次执行时间、启用或暂停，也可以直接删除。

- 定时任务支持定时禁言、定时解禁、定时群打卡、定时群发群和定时群发好友。
- 循环任务按固定分钟间隔向指定群发送内容。
- 群发支持群、好友和群名片三种模式，使用当前账号的全部对象并跳过排除名单。
- 定时任务连续失败 10 次会自动停用并通知主人。

### 点歌

官方 `get_music_ark` 只支持 QQ 和网易云（`163`）两种音乐卡片；酷狗没有官方卡片类型，卡片模式下会自动回退链接。

- `点歌功能` 是类目菜单，不会触发搜索；搜索格式为 `点歌 <歌名>` 或 `搜歌 <歌名>`。
- `开启点歌功能` 会同时开启“允许外部搜索”；卡片/语音点歌必须开启搜索。
- 搜索后默认列出最多 5 首，60 秒内回复序号；可关闭选歌直接发送第一条。
- 回复模式支持链接、群/好友语音和音乐卡片；语音上传失败回退卡片，卡片失败回退链接。
- 控制台“点歌线路”按优先级管理 Meting、Meting 兼容和网易直连线路，首选来源失败后自动尝试其他来源。
- 实际可用音质取决于所配置的接口，不保证所有来源都有音频直链。

### 红包助手

红包能力基于萌卡官方 `red_packet` 消息段和官方领取接口，不修改协议、不伪造客户端，要求 Android 协议账号。

- 五类独立开关：普通、拼手气、口令、专属、语音；可分别发送 `开启/关闭普通红包` 等指令。
- 按 `delay_ms + jitter_ms` 延迟领取；领取前查询总额与份数，低于期望门槛时跳过。
- 支持监听群名单、只领不回复名单、每日上限和每分钟限流。
- 群/人员/标题关键词支持包含与排除，可直接用 `添加红包关键词`、`添加红包排除词` 维护。
- 到账后默认延迟 3 秒发送 `xxlb`，回复支持 `{amount}`、`{sender}`、`{sender_id}`、`{group}`、`{group_name}`、`{title}`。
- 账本按 `self_id + protocol_id` 隔离，默认保留 30 天；控制台可查看群红包排行和最近处理记录。
- 自己发送的红包默认也会领取；可关闭“领取自己发送的红包”，或发送 `关闭领取自己红包`。
- 语音红包默认使用内置 AI 语音，也可切换为自定义 TTS 或固定语音文件/URL。官方接口要求先发送匹配语音才能领取；关闭“发送语音”后语音红包会跳过。
- 失败不自动重试；查询失败可配置为跳过或继续领取。

### 授权

授权是本地管理能力，不连接授权站、不发心跳、不远程下发配置。

- 卡密格式为 `QCA-XXXX-XXXX-XXXX`，由主人或代理在本地生成，支持天数、数量、备注和代理归属。
- 群主在群内发送 `使用卡密 <卡密>`（别名 `兑换卡密`、`授权本群`）为本群开通或续期，续期从当前到期时间顺延。
- 代理在配额内生成卡密，配额 0 表示不限；支持启用、停用和配额统计。
- 分群授权按账号与群隔离，支持手动授权、续期和撤销。
- 授权门禁默认关闭。开启后，未授权群的群管指令会被拦截；主人、机器人自身、授权类指令和红包兑换不受影响。红包引擎在门禁开启时只处理已授权群。

### 在线更新

控制台“系统 → 在线更新”支持检查、下载、校验和托管导入，也可以直接在聊天中发送 `在线更新`、`检查更新` 或 `立即更新`。

- 默认更新源为 `haircv/Mengka-QQ-Cloud-Assistant` 的 GitHub Release，也可改为其他 `owner/repo` 或自定义清单地址。
- 发布包命名必须包含 `windows-amd64`、`linux-amd64`、`linux-arm64` 之一，支持 ZIP、TAR.GZ 和 TGZ。
- 下载后校验压缩包 SHA256（若提供）、`mengka-plugin.json` 的 `plugin_id=qq-cloud-assistant` 与版本，以及 `SHA256SUMS` 中程序入口的哈希。
- 仅在萌卡托管模式安装：先登录萌卡管理员，再调用托管导入接口；服务节点可自动选择，多节点时需填写节点 ID。
- 导入完成后会尝试自动启用新实例；启动失败会保留更新结果并提示手动启用。
- 在线更新只支持安装高于当前版本的新版本，不提供重装当前版本；已是最新时按钮不可用。
- GitHub 下载失败会自动重试 3 次（单次 90 秒超时）；提交更新后控制台会等待插件重启并自动刷新页面。
- 启动助手优先通过 Windows 任务计划、WMI 或 Linux `systemd-run` 启动，避免萌卡替换文件时连同子进程一起终止；控制台可查看“自动启用日志”。
- 独立/控制台模式只允许检查和下载，不会自动替换程序。
- GitHub API 未认证时有速率限制；可设置环境变量 `QCA_GITHUB_TOKEN`（只读权限即可）提高额度。
- 自动检查默认关闭；开启后每 6 小时检查一次，只提示新版本，安装仍需在控制台确认。

## 数据目录

数据目录按以下顺序解析：

1. `--data-dir` 或环境变量 `QCA_DATA_DIR`
2. 萌卡注入的 `MENGKA_PLUGIN_DATA_DIR`——托管模式的持久数据目录，更新、暂停、重新导入都不会改变
3. 用户配置目录 `%APPDATA%\qq-cloud-assistant`（Linux 为 `~/.config/qq-cloud-assistant`）
4. 旧版可执行目录 `data/` 或 `%LOCALAPPDATA%\qq-cloud-assistant`

托管数据目录为空时，首次启动会自动从用户配置目录或旧版 `data/` 迁移数据库、配置、授权与日志，并在原目录生成 `.pre-migrate-*` 备份。

```text
data/
├── qca.db
├── admin.token
├── global.json
├── permissions.json
├── accounts/<self_id>/<protocol_id>.json
├── groups/<self_id>/<protocol_id>/<group_id>.json
├── media/
├── backup/
└── logs/
```

更换电脑或重新导入前，先退出程序并备份整个数据目录。同一台机器运行多个节点时，请用 `QCA_DATA_DIR` 为每个节点指定独立目录。

## 版本与升级

当前版本为 **1.2.24**，每次正式发布递增版本。更新方式：

1. 在控制台“系统 → 在线更新”检查并安装，或在聊天中发送 `检查更新` / `立即更新`。
2. 也可以从发布页下载对应平台的安装包，在萌卡“插件导入”中重新导入。

萌卡会校验插件程序文件完整性。重新构建、替换可执行文件或更新安装包后，暂停/重启时可能提示“插件程序文件已变更，请重新导入”。这是框架侧校验提示，不是插件数据损坏。处理方式：

1. 暂停插件；
2. 如果旧数据仍在插件安装目录的 `data/`，先备份该目录；
3. 在萌卡 NT 管理后台重新导入对应版本的安装包，并绑定原节点；
4. 1.2.20 首次启动会自动把旧数据迁移到萌卡数据目录；
5. 不要直接覆盖已安装目录内的可执行文件后重启。

> 1.2.13 及更早版本的在线更新不会提交 `node_id`，会被萌卡拒绝为“请选择服务节点”。请手动导入一次 1.2.24，之后即可正常在线更新。

## 常见问题

### 只有菜单有回复，其他指令没反应

这是权限配置问题，不是功能没开启。所有指令默认 Lv5，只有主人/机器人自身可用。可在“权限 → 指令权限”点“严格”恢复全部 Lv5，再把使用的 QQ 加到“主人”；需要群主使用时，单独下调对应指令。

### 发送类目名没有回复

一级菜单就是类目名，例如 `通用功能`、`授权功能`、`红包功能`、`点歌功能`。也可以用 `菜单 <类目名>` 查看。非主人/非自身发送者仍受默认 Lv5 限制而静默，需要在“指令权限”下调对应类目，或把 QQ 加入主人。

### 点歌功能开启了仍没反应

1. 点歌是群级配置，确认顶部群选择器选中了测试群；
2. 功能开关不等于触发权限，确认“点歌”指令级别或当前发送者在主人列表；
3. 确认“允许外部搜索”和“点歌线路”已启用，也可以在群内发送 `开启点歌功能`；
4. 使用 `点歌 晴天` 或 `搜歌 晴天`，不要发送 `点歌功能`（它是类目菜单）。

### 禁言/解禁提示“请 @ 要禁言的成员”

可使用 `禁言 @群成员 600`、`禁言 @QQ号 600`、`禁言 QQ号 600`；解禁同理。若 @ 段缺少数字 ID，会按昵称、UID 映射或引用消息回退解析；仍失败时日志会输出 `禁言目标解析失败` 及消息段字段，便于继续定位。

### 普通红包提示“未取得红包领取凭据 (state=6)”

1.2.20 起恢复为嵌套请求格式：只提交 `group_id`、`sender_id`、`red_packet` 和可选的 `claim_token`，不再平铺 `channel/title`。凭据失败仍按新凭据、无凭据、自己红包延迟重试。自己发送的红包受节点风控影响，仍可能间歇失败。

### 语音红包提示未配置 TTS / 不想在群里发语音

1.2.15 起语音红包默认使用内置 AI 语音，不需要填写 TTS 接口；1.2.20 起音频改用 Base64 上传，不再受萌卡本地媒体目录限制。控制台“红包助手 → 语音红包音频来源”可切换为自定义 TTS 或固定语音文件/URL。官方接口要求先发送匹配语音才能领取，不能只匹配不发送；不需要发送语音时关闭“语音红包发送语音”或直接关闭语音红包类型，插件会跳过而不再报错。

### 控制台登录不上萌卡管理员

萌卡管理端口不固定，不一定是 `127.0.0.1:7891`。登录页会显示实际连接地址；无法连接时，请用数据目录中的 `admin.token` 回退登录。在线更新页的“萌卡管理接口”要填写 Mengka 管理端 Web 地址，不是插件控制台 18084；地址错误返回 502，账号/验证码错误返回 401。

### 更新后没有自动启用

1.2.20 起会自动查找新实例并调用启动接口；如果仍未启用，可手动启动一次 1.2.24。此后助手使用系统任务计划或 `systemd-run`，不再依赖旧插件进程存活。控制台“在线更新 → 自动启用日志”可查看执行记录。

### 数据在哪里？怎么备份？

Windows 默认在 `%APPDATA%\qq-cloud-assistant`，Linux 默认在 `~/.config/qq-cloud-assistant`；萌卡托管模式优先使用 `MENGKA_PLUGIN_DATA_DIR`。退出程序后备份整个数据目录即可，控制和授权数据都在其中。

## 已知限制

- 官方 API 无抽字符接口：字符功能 5 条不注册。
- 官方事件无 poke 通知：被戳处理 6 条不注册。
- 无账号级进群屏蔽/免打扰/群助手接口：6 条不注册。
- 无管理员变更事件：上管/下管提示 6 条不注册；权限缓存按 5 分钟 TTL 刷新。
- 无禁言状态/全禁状态查询接口：自动退出禁言群/全禁群 4 条不注册。
- QQ 指令层的检测更新/更新插件 2 条不注册；在线更新统一在 Web 控制台“系统 → 在线更新”完成。
- 群荣誉、空间动态、打卡、好友申请处理依赖 Android 协议材料，Linux 账号可能降级或不可用。
- 媒体 `file_id` 有效期约 5 分钟，过期后无法撤回或转发。
- 群发、秒赞/秒评、怼人、清屏均有限频与风控风险提示；清屏只撤回缓存内消息，不发送零宽字符。
- 入群验证会话保存在内存，插件重启后未完成会话按过期处理。
- 控制台数据库恢复需要重启插件后生效。
- 授权门禁默认关闭；开启后只拦截未授权群的群内指令，红包引擎额外检查授权，其他自动功能仍按各自开关运行。

## 安全与合规

- 不实现伪造聊天、闪照监控、支付、订单、收款。
- 卡密、分群授权和代理均为本地管理，不连接授权站、不发心跳、不远程下发配置。
- 红包仅通过官方消息段与官方领取接口处理，由用户显式开启；语音红包仅 Android 账号领取，发送语音前会先匹配口令。
- 不采集、不上传用户数据。
- 点歌搜索、语音红包内置/自定义 TTS、固定音频 URL、在线更新检查/下载以及托管模式萌卡管理登录会按需外联；其余功能不外联。
- 不保存 QQ 账号密码；QQ 账号由萌卡 NT 管理。托管控制台登录只转发萌卡管理员凭据，密码不落盘、不写日志；30 天免登录只保存随机会话令牌。
- 日志不输出令牌、Cookie、完整消息内容、红包 `authkey` / `claim_token`。

## 构建与发布（维护者）

公开发行仓库只保留 README 与 `release-notes/`，以下命令用于源码维护。需要 Go 1.25。

```bash
gofmt -w .
go vet ./...
go test ./...
go build ./...
```

一键生成三平台 IPC 包：

```bash
bash scripts/build-all.sh
```

Windows PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-all.ps1
```

产物在 `dist/`，每个包根目录包含 `mengka-plugin.json`、本机可执行文件、`README.txt` 和 `SHA256SUMS`。

推送 `v*` 标签或手动触发 `.github/workflows/release.yml` 会执行测试、构建三平台包并上传 Release；也可以用 `scripts/publish-release.sh` / `publish-release.ps1` 在本机发布。更新说明放在 `release-notes/release-notes-v<版本>.md`。
