# QQ云助手（qq-cloud-assistant）

QQ云助手是面向萌卡 NT 3.0 的 QQ 云端助手插件，功能基线来自 `cloud-assistant 1.0.0`，以原生 IPC 插件形式运行，并自带 Web 控制台。

- 中文名：QQ云助手
- 插件 ID：`qq-cloud-assistant`
- 框架：萌卡 NT 3.0（`mengka-plugin.json` schema 3）
- 接入：`native-ipc-v1`
- 版本：1.2.20
- 授权：本地卡密 / 分群授权 / 代理管理，**无授权站、无应用 ID、无心跳、无联网校验**
- 平台：Windows x64 / Linux x86_64 / Linux ARM64
- 更新日志与下载：https://github.com/haircv/Mengka-QQ-Cloud-Assistant/releases

## 功能概览

- 通用：菜单、类目菜单、帮助、运行状态（登录协议显示为 `Android Pad(9.3.75)`，实时状态末尾显示在线/登录时间/当前时间）、在线更新/检查更新/立即更新
- 群管：踢人、禁言/解禁、上下管、全体禁言、解禁全部、群星/群信息、取码、复读、取直链、加群链接；禁言/解禁支持 @成员、@QQ号、QQ 号，@ 段异常时可按昵称、UID 或引用消息解析目标
- 群配置：模板变量提示；分管、群/全局黑名单仅填写 QQ；清屏/召唤人数/点歌模式与 Web 控制台使用同一群配置
- 提示：入群、退群、被踢、被删、机器人被踢通知与模板；默认全部关闭，按单个群在控制台或发送 `开启入群提示` 等指令开启
- 自动化：防撤、自身撤回、艾特处理、秒赞秒评、点赞、互赞、表情回应、续火、自动说说、自动处理、名片、打卡、资料、备注、头衔、入群验证
- 问答：本群/好友/全局 × 精准/模糊，白名单、延迟、随机回复条数、关键词冷却
- 任务：定时、循环、群发、多源点歌与搜歌
- 账号：主人菜单、触发模式、账号分组、主群
- 红包助手：普通/拼手气/口令/专属/语音五类独立控制及开关指令、群/人员/标题关键词（包含/排除）规则、期望过滤、拟人延迟、到账回复、只领不回复名单、分群配置、账本与排行
- 点歌：QQ/网易云/酷狗多源搜索、选歌、链接/语音/音乐卡片回复、线路优先级与失败换源；音频直链探测，语音失败自动 Base64 回退
- 授权：本地卡密生成/禁用/删除、群主兑换、分群授权与续期、代理配额、可选的授权门禁
- 控制台：59 个目录驱动模块，覆盖总览、账号、群管理、自动化、问答、任务与点歌线路、红包、授权、权限、系统；群号字段从当前账号群列表联想选择（群名/群号），主人、分管、黑名单只填写 QQ；短屏弹窗内容区滚动、操作按钮固定
- 在线更新：GitHub Release 或自定义清单检查新版本，校验插件 ID/版本/SHA256 后在萌卡托管模式下通过管理员会话导入，并自动调用萌卡接口启用插件；登录支持萌卡管理员账号+密码+图形验证码；通用功能提供“在线更新 / 检查更新 / 立即更新”指令

指令总数：**382 条**（原 333 条 + 授权 16 条 + 红包 29 条 + 语音点歌 1 条 + 在线更新 3 条）。清单声明 **54 个 action**；源码中 29 条能力缺失指令不注册，控制台只显示原因，不提供空操作。

## 权限

| 级别 | 名称 | 说明 |
|---|---|---|
| 0 | 黑名单 | 不响应指令与交互式自动回复 |
| 1 | 群员 | 仅响应下调到 Lv1 的指令 |
| 2 | 管理 | 事件角色为管理员 |
| 3 | 群主 | 事件角色为群主 |
| 4 | 分管 | 群配置中的分管名单 |
| 5 | 主人 | 全局主人、账号主人、机器人自身 |

- 所有指令默认仅 Lv5 可触发，包括红包/授权/点歌；群主兑换或代理生成需由主人在控制台显式下调对应指令级别，处理器仍校验身份。
- 机器人自身 QQ 发送消息时直接判定 Lv5。
- 指令可配置级别为 1–5；`0` 是黑名单，不能分配给指令。
- 控制台提供“严格 / 推荐 / 自定义”权限预设。

## 红包助手

红包能力基于萌卡官方 `red_packet` 消息段与红包接口，不修改协议、不伪造客户端；要求 Android 协议账号。

- 五类独立开关：普通、拼手气、口令、专属、语音；6/32/65536/1024 等明确 `channel` 优先，`channel=1/0` 再结合 `type` 识别普通/拼手气。指令支持 `开启/关闭普通红包`、`开启/关闭拼手气红包`、`开启/关闭口令红包`、`开启/关闭专属红包`、`开启/关闭语音红包`。
- 普通/拼手气/专属：请求使用 `group_id`、`sender_id` 与嵌套 `red_packet`，不再把 `channel/title` 等字段平铺到顶层；查询详情取得 `claim_token`。凭据缺失、失效或返回 `state=6` 时依次尝试新凭据、无凭据自动获取、自己红包延迟重试。
- 普通/拼手气/专属：按 `delay_ms + jitter_ms` 延迟领取；专属红包由上游校验接收人，非目标会按领取失败记录。
- 口令红包：先发送去除首尾空白的口令，再用发送结果的 `client_seq`、`msg_random` 领取，不用红包消息的 `msg_seq`，也不传 `claim_token`。
- 语音红包：默认使用内置 AI 语音生成标题录音，也可选择自定义 TTS 或固定语音文件/URL；随后 `upload_red_packet_voice` 匹配 → 发送群语音 → `grab_group_voice_red_packet`。官方接口要求先发送语音，无法在不发送语音的情况下领取；关闭“发送语音”后语音红包会跳过，不产生 TTS 错误。
- 群/人员/标题关键词规则：支持包含与排除；指令 `添加/删除红包关键词`、`添加/删除红包排除词`、`查看/清空红包关键词` 可直接维护，标题提取兼容 `title/wish/data.title/red_packet.content` 等字段。
- 期望过滤：领取前查询总额与份数，`每份期望 < min_expected_fen` 时跳过并记录。
- 到账确认：以 `retcode=0 && state=0` 判定成功，金额只取 `recv_object.amount`（分）；缺少 `state` 或金额时不会伪报成功。
- 到账回复：默认延迟 3 秒发送 `xxlb`，支持 `{amount}`、`{sender}`、`{sender_id}`、`{group}`、`{group_name}`、`{title}`；金额未知默认不回复。
- 限额：监听群名单、只领不回复名单、每日上限、每分钟限流；同一账号同一 `listid` 只处理一次。
- 账本：按 `self_id + protocol_id` 隔离，记录类型、查询总额/份数、到账金额、领取响应、完整流程、回复状态与原因；默认保留 30 天。
- 自己发送的红包默认也会领取；可在控制台“红包助手”关闭“领取自己发送的红包”，或发送 `关闭领取自己红包`。关闭后会记录“跳过·自己发送”。
- 失败不自动重试；查询失败可选择跳过或继续领取。


## 点歌与搜歌

官方 `get_music_ark` 仅支持 `qq` 与 `163`（网易云）两种音乐卡片；酷狗没有官方卡片类型，卡片模式下自动回退链接。

- `点歌功能` 是类目菜单，不会触发搜索；搜索格式为 `点歌 <歌名>` / `搜歌 <歌名>`，可写 `点歌 QQ 晴天`、`点歌 网易云 晴天`、`点歌 酷狗 晴天` 临时指定来源。
- `开启点歌功能` 会同时开启“允许外部搜索”；卡片/语音点歌必须开启搜索，否则会给出明确提示而不再静默回退链接。
- 线路：控制台“点歌线路”按优先级管理 Meting / Meting 兼容 / 网易直连线路，可启用禁用；首选来源失败后自动尝试其他来源线路。
- 选歌：搜索后默认列出最多 5 首，60 秒内回复序号；可关闭选歌直接发送第一条。
- 回复模式：链接、群/好友语音、音乐卡片；语音上传失败回退卡片，卡片失败回退链接。
- 音质：线路的 `quality` 会作为接口参数或提示，实际可用音质取决于所配置接口；不保证所有来源都有音频直链。
- 外部请求仅发生在用户主动点歌时；搜索接口不可用时回退为搜索链接。

## 授权

授权是本地管理能力，不包含任何联网验证：

- 卡密格式 `QCA-XXXX-XXXX-XXXX`，本地生成，支持套餐、天数、备注、代理归属。
- 群主在群内发送 `使用卡密 <卡密>`（别名 `兑换卡密`、`授权本群`）为本群开通或续期，续期从当前到期时间顺延。
- 代理在配额内生成卡密；配额 0 表示不限；支持启用/停用、已生成/已兑换统计。
- 分群授权按账号与群隔离，支持手动授权、续期、撤销。
- 授权门禁默认关闭，开启后未授权群的群管指令会被拦截；主人和机器人自身不受影响，授权类指令与红包兑换始终可用。门禁不改变自动功能的开关语义，但红包引擎在门禁开启时只处理已授权群。

常用指令：

```text
生成卡密 30 5            # 主人或代理生成
使用卡密 QCA-XXXX-XXXX-XXXX
查询授权 [群号]
授权群 123456789 30
撤销授权 123456789
添加代理 10001 代理A
设置代理配额 10001 100
代理列表
```

## 安装

1. 在萌卡 NT 管理后台打开“插件导入”。
2. 选择对应系统的安装包：
   - `qq-cloud-assistant-1.2.20-windows-amd64.zip`
   - `qq-cloud-assistant-1.2.20-linux-amd64.tar.gz`
   - `qq-cloud-assistant-1.2.20-linux-arm64.tar.gz`
3. 选择绑定节点并导入。
4. 启动插件。
5. 首次启动会在数据目录生成 `admin.token`，并向框架日志输出一次管理令牌。
6. 打开 `http://127.0.0.1:18084/`。运行在萌卡内时默认使用萌卡管理员账号、密码和图形验证码登录；也可点“使用本地管理令牌”回退到 `admin` + `admin.token`。
7. 在“账号列表”确认账号与协议实例，在“主人”页添加主人 QQ（或直接用机器人自身 QQ 发指令）。
8. 同一 QQ 的 Android 与 Linux/PC 同时在线时，默认仅 Android 实例响应，Linux/PC 静默；可在“触发模式”关闭“仅 Android 生效”。
8. 在“指令权限”页选择“推荐”预设，或手动下调菜单/帮助/打卡/申请头衔/互赞/点歌。
9. 发送“菜单”验证。

如果 18084 被占用，控制台会依次尝试 18085–18093，并在日志中输出实际地址。

### 升级说明

萌卡会校验插件程序文件完整性。重新构建、替换可执行文件或更新安装包后，暂停/重启时可能提示“插件程序文件已变更，请重新导入”，这是框架侧的校验提示，不是插件数据损坏。处理方式：

1. 暂停插件；
2. 如果旧数据仍在插件安装目录的 `data/`，先备份该目录；
3. 在萌卡 NT 管理后台重新导入对应版本的安装包，并绑定原节点；
4. 1.2.20 首次启动会自动把旧数据迁移到萌卡数据目录（升级保留数据）；
5. 不要直接覆盖已安装目录内的可执行文件后重启。

> 1.2.13 及更早版本的在线更新不会提交 `node_id`，会被萌卡拒绝为“请选择服务节点”。请手动导入一次 1.2.20，之后即可正常在线更新。

## 数据目录

解析顺序：

1. `--data-dir` 或环境变量 `QCA_DATA_DIR`
2. 萌卡注入的 `MENGKA_PLUGIN_DATA_DIR`——托管模式的持久数据目录，更新、暂停、重新导入都不会改变
3. 用户配置目录 `%APPDATA%\qq-cloud-assistant`（Linux `~/.config/qq-cloud-assistant`）
4. 旧版可执行目录 `data/` 或 `%LOCALAPPDATA%\qq-cloud-assistant`

托管数据目录为空时，首次启动会自动从用户配置目录或旧版 `data/` 迁移数据库、配置、授权与日志，并在原目录生成 `.pre-migrate-*` 备份。重新导入插件包后继续使用同一数据目录，配置、授权、红包账本不会丢失。若旧数据在未知目录，可把旧 `data/` 整个复制到当前数据目录，或首次启动时设置 `QCA_DATA_DIR` 指向旧目录。同一台机器运行多个节点时，请用 `QCA_DATA_DIR` 为每个节点指定独立目录。

目录内容：

```text
data/
├── qca.db
├── admin.token
├── global.json
├── permissions.json
├── accounts/<self_id>/<protocol_id>.json
├── groups/<self_id>/<protocol_id>/<group_id>.json
├── media/
├── backup/
└── logs/
```

升级保留 `data/`；卸载默认保留数据。

## 控制台

- 默认仅监听 `127.0.0.1`，令牌只保存在后端。
- 左侧栏支持桌面 224px ↔ 64px 平滑收起/展开；≤900px 自动切换为抽屉 + 遮罩；滚动条为透明轨道细样式。
- 全宽度响应式：头部操作区自动换行，卡片/表单自动降列，表格在窄屏容器内横向滚动，窗口缩放不遮挡内容。
- 登录后有 HttpOnly 会话 Cookie + CSRF 校验；5 次失败锁定 5 分钟。
- 托管模式由 `managed.Load()` 识别：控制台默认走萌卡管理员账号、密码、图形验证码登录；独立/控制台模式使用本地管理令牌。
- 萌卡管理端口不固定，不一定是 `127.0.0.1:7891`；登录页会显示实际连接地址，无法连接时请用数据目录 `admin.token` 回退登录。
- 同一 QQ 多协议同时在线时，默认 Android 实例处理事件，Linux/PC 实例静默；Android 离线后 Linux/PC 自动恢复处理。
- 账号选择器使用 `昵称（QQ / 协议ID）`；群级模块额外显示群选择器。
- 运行概览与账号列表会逐账号刷新 `get_bot_info`，好友/群数量为 0 时回退 `get_friend_list` / `get_group_list` 计数。
- 运行状态显示 CPU 占用、系统内存已用/总量/占比、磁盘总量/剩余，以及 Worker、协程、进程内存和指令数；“能力”页明确区分管理 API 版本与 Action/事件数量。
- 运行概览的 QQ 账号数按 `self_id` 去重、群聊按群号去重，另列协议实例数，避免同一 QQ 多协议重复统计。
- 关于页版本号从后端实时读取，与 `/api/health` 和发布版本一致。
- 红包助手页包含：五类开关、语音发送开关与音频来源（内置 AI 语音/自定义 TTS/固定音频）、规则表，确认领取/累计金额/成功回复/平均领取耗时、运行概况、群红包排行、最近处理记录、账号级设置、监听群/只领不回复名单；群设置页可按群覆盖延迟、门槛、回复等。
- 授权页包含：卡密管理、分群授权、代理管理、授权设置；任务页新增“点歌线路”表。
- 支持的表格来源：白名单、回复池、问答、定时任务、循环任务、群发任务、账号分组、群分管、主人、黑名单、指令权限、审计日志、卡密、分群授权、代理、红包记录、红包规则、点歌线路。
- 一键操作会创建任务，可在“运行状态”查看进度。
- 备份导出包含配置与数据库；恢复时配置立即生效，数据库暂存为 `qca.db.restore`，重启插件后替换。
- 支持 `--console-only`：只启动控制台，不连接 IPC，适合 UI 开发与验收。

## 在线更新

控制台“系统 → 在线更新”支持检查、下载、校验与托管导入：

- 默认更新源：`haircv/Mengka-QQ-Cloud-Assistant` 的 GitHub Release；也可改为其他 `owner/repo` 或自定义更新清单地址。
- 发布包命名必须包含 `windows-amd64`、`linux-amd64`、`linux-arm64` 之一，支持 ZIP/TAR.GZ/TGZ。
- 下载后校验压缩包 SHA256（若提供）、`mengka-plugin.json` 的 `plugin_id=qq-cloud-assistant` 与版本、`SHA256SUMS` 中程序入口的哈希。
- 仅在萌卡托管模式安装：先登录萌卡管理员（账号、密码、图形验证码），再调用 `/api/v1/plugins/managed/import` 导入；权限变化时需二次确认。
- 服务节点：默认读取萌卡托管节点配置；只有一个可用节点时自动选择，多节点时在“在线更新设置 → 服务节点 ID”填写 `/api/v1/nodes/options` 中的节点 ID。
- 导入完成后自动查找新实例并调用 `action=start` 启用；启动失败会保留更新结果并提示手动启用。
- 萌卡管理端 CSRF 自动兼容：读取 `XSRF-TOKEN` 等 Cookie，缺失时先加载管理首页补发，写请求同时发送 `X-XSRF-TOKEN` / `X-CSRF-Token`，遇到 403 自动刷新令牌后重试一次。
- 1.2.20 起启动助手优先通过 Windows 任务计划或 Linux `systemd-run` 启动，避免萌卡替换文件时连子进程一起终止；控制台“在线更新 → 自动启用日志”可查看执行记录。
- 从旧版本升级到 1.2.20 后如果仍未自动启用，可手动启动一次 1.2.20；此后助手使用系统任务计划，不再依赖插件进程存活。

## 常见问题

### 只有菜单有回复，其他指令没反应

这是权限配置问题，不是功能没开启。所有指令默认 Lv5，只有主人/机器人自身可用；如果之前应用过“推荐”预设，菜单/帮助/点歌等会被下调，其他指令仍是 Lv5。可在“权限 → 指令权限”点“严格”恢复全部 Lv5，再把使用的 QQ 加到“主人”；需要群主使用时单独下调对应指令。

### 发送一级类目名没有回复

一级菜单就是类目名（`通用功能`、`授权功能`、`红包功能`、`点歌功能` 等）。1.2.4 起机器人自身发送也会正常回复；非主人/非自身发送者仍受默认 Lv5 限制而静默，需要在“权限 → 指令权限”下调对应类目，或把 QQ 加入主人。旧名 `通用`、`授权`、`红包` 已移除，不再触发菜单。连续快速发送时受发送限速影响，回复可能稍晚到达。

### 点歌功能在控制台开启了仍没反应

1. 点歌模块是**群级配置**，确认顶部群选择器选中了测试群；
2. 功能开关不等于触发权限，确认“点歌”指令级别（默认 Lv5）或当前发送者在主人列表；
3. 确认“允许外部搜索”和“点歌线路”已启用；也可在群内发送 `开启点歌功能`，会一并开启搜索；
4. 使用 `点歌 晴天` 或 `搜歌 晴天`，不要发送 `点歌功能`（它是类目菜单）。

### 禁言/解禁提示“请 @ 要禁言的成员”

可使用 `禁言 @群成员 60`、`禁言 @QQ号 60`、`禁言 QQ号 60`；解禁同理。若 @ 段缺少数字 ID，1.2.20 会按昵称、UID 映射或引用消息回退解析；仍失败时日志会输出 `禁言目标解析失败` 及消息段字段，便于继续定位。

### 普通红包提示“未取得红包领取凭据 (state=6)”

1.2.20 起恢复为上一版的嵌套请求格式：只提交 `group_id`、`sender_id`、`red_packet` 和可选的 `claim_token`，不再平铺 `channel/title`。凭据失败仍按新凭据、无凭据、自己红包延迟重试。自己发送的红包受节点风控影响，仍可能间歇失败。

### 语音红包提示未配置 TTS / 不想在群里发语音

1.2.15 起语音红包默认使用内置 AI 语音，不需要填写 TTS 接口；1.2.20 起音频改用 Base64 上传，不再受萌卡本地媒体目录限制。控制台“红包助手 → 语音红包音频来源”可切换为自定义 TTS 或固定语音文件/URL。官方接口要求先发送匹配语音才能领取，**不能只匹配不发送**；不需要发送语音时关闭“语音红包发送语音”或直接关闭语音红包类型，插件会跳过而不再报错。

## 已知限制

- 语音红包账号必须为 Android；官方接口要求先发送匹配语音，不能只匹配不发送。默认使用内置 AI 语音，无需配置；也可改用自定义 TTS 或固定音频。关闭“发送语音”时语音红包会跳过。
- 红包类型优先按明确 `channel` 识别；`channel=1/0` 时结合 `type` 区分普通与拼手气，若上游既不提供明确 channel 也不提供 type，仍可能无法区分。
- 口令红包必须先成功发送口令，且发送结果需要返回有效的 `client_seq`、`msg_random`；缺失时放弃领取并记录原因。
- 领取金额未知时不会发送感谢语；查询失败策略可配置为跳过或继续。
- 官方 `get_music_ark` 不支持酷狗卡片；酷狗卡片模式回退链接/语音。
- 点歌搜索和语音红包内置/自定义 TTS 依赖外部接口；接口不可用时回退搜索链接或记录失败，固定音频模式不依赖 TTS。
- 官方 API 无抽字符接口：字符功能 5 条不注册。
- 官方事件无 poke 通知：被戳处理 6 条不注册。
- 无账号级进群屏蔽/免打扰/群助手接口：6 条不注册。
- 无管理员变更事件：上管/下管提示 6 条不注册；权限缓存按 5 分钟 TTL 刷新。
- 无禁言状态/全禁状态查询接口：自动退出禁言群/全禁群 4 条不注册。
- QQ 指令层的检测更新/更新插件 2 条不注册；在线更新统一在 Web 控制台“系统 → 在线更新”完成。
- 群荣誉、空间动态、打卡、好友申请处理依赖 Android 协议材料，Linux 账号可能降级或不可用。
- 媒体 `file_id` 有效期约 5 分钟，过期后无法撤回/转发。
- 群发、秒赞/秒评、怼人、清屏均有限频与风控风险提示；清屏只撤回缓存内消息，不发送零宽字符。
- 入群验证会话保存在内存，插件重启后未完成会话按过期处理。
- 控制台数据库恢复需要重启插件后生效。
- 授权门禁默认关闭；开启后只拦截群内指令，红包引擎额外检查授权，其他自动功能仍按各自开关运行。

## 安全与合规

- 不实现伪造聊天、闪照监控、支付、订单、收款。
- 卡密、分群授权、代理均为本地管理，不连接授权站、不发心跳、不远程下发配置。
- 红包仅通过官方消息段与官方领取接口处理，由用户显式开启；语音红包仅 Android 账号领取，发送语音前会先匹配口令。
- 不采集、不上传用户数据。
- 点歌搜索、语音红包内置/自定义 TTS、固定音频 URL、在线更新检查/下载以及托管模式萌卡管理登录会按需外联；其余功能不外联。
- 不保存 QQ 账号密码；QQ 账号由萌卡 NT 管理。托管控制台登录只转发萌卡管理员凭据，密码不落盘、不写日志。
- 日志不输出令牌、Cookie、完整消息内容、红包 `authkey`/`claim_token`。
